Capstone · infrastructure workstream

Everything I built, and why each piece exists

The ShopNow app needs somewhere to run. This is the AWS infrastructure that gives it one — described entirely in Terraform, so it can be rebuilt or deleted with a single command.

The whole thing in one picture

The five pieces and what each is for

Network

VPC

Your own private network inside AWS. Every server has to live in a network — without one there is nowhere to put anything.

Public subnets can be reached from the internet: the load balancer and Jenkins go here. Private subnets cannot: the worker nodes running your app go here, so nobody can reach them directly. They still reach outward through the NAT gateway to download images.

Storage for images

ECR

A private Docker registry. Avinash builds the app into images; they have to live somewhere the cluster can download from. Docker Hub is public, so that would publish the project's code to the world.

Three repositories — frontend, admin, backend. MongoDB does not need one because it uses the official public image.

Compute

EKS

Managed Kubernetes. You could run containers on a plain EC2 box with docker run — until it reboots and nothing comes back, or a deploy takes the site down mid-swap. Kubernetes restarts crashed containers, runs several copies, and replaces them one at a time.

AWS runs the hard part (the control plane) for about $0.10/hour. You manage the worker nodes — two EC2 instances that actually run the containers.

Permissions

IAM

Three things here need AWS permissions and none of them is a person: the control plane, the worker nodes, and Jenkins.

Each gets a role instead of a password. The alternative is pasting an access key into Jenkins, where it sits on a server forever. A role gives temporary credentials that rotate on their own.

Shared record

S3 remote state

Terraform keeps a file recording everything it created. That is how it knows next time what already exists.

On a laptop it would mean nobody else can run Terraform, and a dead laptop would leave AWS resources nobody can account for. In S3 it is shared, versioned, encrypted, and locked so two people cannot write at once.

Terraform basics

What is Terraform and why use it instead of the AWS console?
It builds cloud resources from files that describe what you want, rather than from clicking through forms. That gives you four things clicking cannot: you can rebuild the same environment on demand, review changes before they happen with plan, track every change in git, and delete everything cleanly with destroy instead of hunting for leftovers.
What is the state file and why is it in S3?
It records every resource Terraform has created, so next run it knows what already exists. It is in S3 because four people share this project — on one laptop, nobody else could run Terraform without creating duplicates, and a lost laptop would mean nothing knows what exists in AWS. S3 adds versioning to roll back a corrupted state, encryption because the file holds resource IDs, and locking so two simultaneous applies cannot overwrite each other.
Why is bootstrap a separate stack?
Chicken and egg. The S3 backend cannot store the state of the bucket that is the backend, because the bucket does not exist yet. So bootstrap keeps its state in a local file, creates the bucket, and is then essentially never run again.
What is the difference between resource, variable and output?
resource creates something in AWS — it is the only one that does. variable declares a value the folder accepts as input, referred to as var.name. output publishes a value so the calling code, or a person, can use it. Without an output, a value stays trapped inside its module even though the resource exists.
Why modules instead of one big file?
Reuse and blast radius. A module is like a function: modules/vpc describes how to build a VPC without saying what size or where. A future envs/prod calls the same module with different numbers, so the two environments cannot silently drift apart. It also means everything about the network is in one folder rather than scattered.
What is the difference between plan and apply?
plan reads the real state of AWS, compares it to the code, and shows what it would change — it creates nothing and costs nothing. apply executes it. Running plan -out=tfplan then apply tfplan applies exactly what you reviewed, with no chance of something changing in between. That is what a pipeline does.
Why can't the backend block use variables?
Terraform has to find and load the state file before it can evaluate anything else, including variables. So the backend is configured with a separate file passed at init time: terraform init -backend-config=backend.hcl. That also lets a second environment point at a different bucket with no code change.
What is the difference between count and for_each?
count gives a list indexed by position, so removing a middle item renumbers everything after it and Terraform destroys and recreates them. for_each gives a map keyed by name, so removing one leaves the others untouched. Subnets use count because they are interchangeable; ECR repositories use for_each so deleting admin does not disturb frontend.

Networking

Why public and private subnets rather than just one kind?
Different jobs. Load balancers and the NAT gateway have to be reachable from the internet, so they go in public subnets. Worker nodes running the application should not be reachable, so they go in private ones. Nodes still reach outward through NAT to pull images and talk to the EKS API — outbound works, inbound does not.
Internet gateway versus NAT gateway?
An internet gateway is two-way and free: the internet can reach your resources and they can reach out. A NAT gateway is outbound only and costs around $32/month plus data charges: private resources can start a connection out, nothing outside can start one in. That one-way property is the entire security argument for private subnets.
What do the kubernetes.io subnet tags do?
When the ingress controller creates a Service of type LoadBalancer, the AWS cloud controller has to work out which subnets to place the load balancer in. It looks for kubernetes.io/role/elb=1 on public subnets and internal-elb on private ones. Without them, provisioning fails with a subnet-discovery error — and nothing in the Kubernetes error mentions tags, so it is a confusing failure.
Why two availability zones?
EKS requires subnets in at least two — it refuses to create a cluster otherwise. Beyond the requirement, AZs are physically separate data centres, so spreading nodes across two means one failing does not take the whole application down.
Why one NAT gateway instead of one per AZ?
Cost. Each is about $32/month before data charges. One per AZ is the common tutorial default and triples that for no benefit in a dev environment. The code supports either — single_nat_gateway = false switches it — and per-AZ would be right in production, where losing one AZ's NAT should not affect the other.
How did you decide the CIDR ranges?
The VPC is 10.0.0.0/16 and Terraform computes the subnets with cidrsubnet(vpc_cidr, 4, i), which adds four bits and takes block i — giving 10.0.0.0/20, 10.0.16.0/20 and so on. Computing them means they never overlap and they recalculate correctly if the AZ count changes.

EKS and Kubernetes

Why Kubernetes at all, rather than just running Docker on EC2?
Docker on EC2 works until the server reboots and nothing comes back, or traffic doubles and you need a second copy, or a deploy takes the site down during the swap. Kubernetes handles restarting crashed containers, running several replicas, and rolling updates one pod at a time.
Why EKS rather than installing Kubernetes yourself?
Kubernetes has a control plane (the brain) and worker nodes (the machines). The control plane is genuinely hard to install and keep healthy — etcd, certificates, upgrades. EKS runs it for around $0.10/hour and you only manage nodes.
What is IRSA and why does the EBS CSI driver need it?
IAM Roles for Service Accounts. Every EKS cluster publishes an OIDC identity endpoint; registering it with IAM means a pod's service account token can be exchanged for temporary AWS credentials. The condition in the trust policy names one specific service account, so only the EBS CSI controller can assume that role. The alternative — attaching EBS permissions to the node role — would let every pod on that node create and delete volumes.
Why does the node group need an explicit depends_on?
Terraform infers ordering from references, so it knows the node group needs the IAM role. What it cannot see is that the role needs its policies attached first. Without depends_on, nodes occasionally launch a moment before they are permitted to join the cluster and fail. It is the standard example of when depends_on is genuinely necessary.
Why ignore_changes on desired_size?
Once the autoscaler or HPA scales the group to three nodes, reality no longer matches desired_size = 2 in the code. Without that lifecycle rule, the next apply would scale it back down. It means "I set the initial value, something else owns it after that."
Why Spot instances, and what is the risk?
Spare AWS capacity at roughly 60–70% off. The risk is reclamation with a two-minute warning, which is fine here because the app is replicated and stateless and EKS drains the node gracefully. MongoDB is the one stateful piece — in production it would sit on on-demand nodes or move to a managed database.
How does Jenkins get kubectl access without editing aws-auth?
EKS Access Entries. Historically you hand-edited a ConfigMap called aws-auth inside the cluster, where a typo could lock everyone out permanently. Access Entries are a proper AWS API, so Terraform creates one for the Jenkins role and associates the cluster-admin policy with it.
What is a StorageClass and why does MongoDB need one?
It tells Kubernetes how to turn a storage request into a real disk. EKS ships no default, so a PersistentVolumeClaim with no storage class stays Pending forever. Terraform installs the EBS CSI driver; the gp3 StorageClass tells Kubernetes to use it. It also sets WaitForFirstConsumer, which delays creating the volume until a node is chosen — EBS volumes cannot cross availability zones, so binding immediately can strand a pod from its own disk.

Cost and security

What does this cost, and what did you do about it?
Roughly $0.30–0.35/hour running: the control plane is $0.10, two Spot nodes about $0.026, one NAT gateway $0.045, the rest pennies. Decisions in the code: Spot rather than on-demand, one shared NAT rather than one per AZ, ECR lifecycle policies so image storage stays flat, seven-day log retention, 20 GiB root volumes instead of 50, and non-current state versions expiring after 30 days.
Why does Jenkins use an instance profile instead of access keys?
An access key is a long-lived secret that would sit on the Jenkins server indefinitely, and anyone who reads it has the AWS account. An instance profile makes AWS hand the machine temporary credentials that rotate automatically and cannot be copied off. The AWS CLI, Docker and kubectl all pick them up with no configuration.
Why is one IAM statement scoped to specific ARNs and another wildcarded?
Every ECR action in the policy is scoped to the three repository ARNs except ecr:GetAuthorizationToken, which AWS does not support scoping to a repository — it physically cannot be narrowed. The rest are least-privilege.
Why not commit the state file to git?
It contains resource IDs and can contain secrets in plain text, git has no locking so two people would produce merge conflicts in a machine-generated file, and it would be one more thing to forget. The .gitignore excludes it deliberately.

Your work and the team

What exactly was your contribution?
The whole infrastructure layer: VPC with public and private subnets across two AZs, internet and NAT gateways, route tables, security groups, three ECR repositories with lifecycle policies, IAM roles for the cluster, the nodes and Jenkins, the EKS cluster with a Spot node group and five add-ons, and remote state in S3 with locking. Everything the other three workstreams run on top of.
How do your teammates get what they need from you?
Terraform outputs. Kaushik takes the Jenkins instance profile, security group and a public subnet ID; Avinash takes the ECR URLs, cluster name and the Docker build argument; Ravi takes the private subnet IDs and node group name. Nobody has to look anything up in the AWS console.
What would you do differently with more time?
Add VPC endpoints so ECR traffic avoids the NAT gateway's data charges, install Cluster Autoscaler or Karpenter so nodes scale automatically rather than sitting at a fixed range, narrow the Jenkins Terraform permissions from PowerUserAccess to a hand-written least-privilege policy, and add a prod environment — the module structure already supports it.
What was the hardest problem you hit?
Pick a real one and be specific. Good candidates: discovering the team was split across two AWS accounts, which meant the cluster could not pull images from a teammate's private ECR; or the ordering problem where add-ons must wait for nodes to exist, since their own pods need somewhere to be scheduled.
